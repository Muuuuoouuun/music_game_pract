# 목업 공통 브리프 (시안 A / B / C)

세 시안은 **같은 제품, 같은 게임 엔진 규칙**을 서로 다른 디자인 방향으로 보여준다.
각 시안은 단일 HTML 파일(외부 빌드 없음)로, 브라우저에서 바로 열어 **실제로 플레이할 수 있는** 인터랙티브 목업이다.

## 제품 한 줄

실제 피아노·전자피아노(MIDI)를 컨트롤러로 쓰는 리듬게임. 떨어지는 노트에 맞춰 진짜 건반을 치면
실시간으로 판정(Perfect / Great / Good / Miss)하고, 점수·콤보·정확도·랭크로 보상한다.
"화면을 두드리는 리듬게임이 아니라, 진짜 악기를 연주하는 게임."

## 각 시안에 반드시 들어갈 화면 (한 파일 안에서 탭/스텝으로 전환)

1. **홈 / 곡 선택** — 곡 카드(제목, 작곡가, BPM, 난이도, 최고 점수/랭크), 입력 장치 상태
   (Web MIDI 기기 감지 시 기기 이름 표시, 없으면 "PC 키보드로 플레이 중").
2. **새 곡 만들기(Import)** — 세 가지 소스:
   - YouTube 링크 붙여넣기 (예시 URL 미리 채움)
   - 오디오 파일 업로드 (mp3/wav)
   - 악보 업로드 (MusicXML / MIDI / PDF·이미지)
   "변환 시작"을 누르면 파이프라인 진행을 타이머로 시뮬레이션:
   `오디오 가져오기 → 음원 분리(Demucs: 피아노/보컬/드럼/베이스) → 채보(Basic Pitch) → 템포·박자 분석 → 양손 분리 → 난이도 생성(Easy/Normal/Original) → 완료`
   악보 소스일 때는 `악보 인식(OMR: Audiveris/oemer) → MusicXML 파싱 → 박자 그리드 정렬 → 완료`.
   하단에 작은 안내: "본인이 권리를 가진 음원·악보만 업로드하세요."
3. **플레이(메인, 가장 공들일 화면)** — 아래 "게임 엔진 규칙" 그대로 동작.
4. **결과** — 랭크(S/A/B/C/D), 점수, 정확도, 판정별 개수, 최대 콤보, Full Combo/Perfect Play 배지,
   타이밍 분포(빠름/느림 히스토그램), 마디별 정확도 히트맵, AI 코치 한 줄
   (예: "7마디 왼손이 평균 80ms 늦어요. BPM 80으로 낮춰 3번 연습해 보세요").
   실제 플레이 후엔 실제 통계, 처음 열었을 땐 예시 데이터(예시임을 표시).

## 게임 엔진 규칙 (세 시안 공통 — 숫자 그대로 지킬 것)

### 곡 데이터: "Ode to Joy" (Beethoven, 퍼블릭 도메인), 4/4, BPM 100, 8마디
노트 형식 `[midi, startBeat, durBeats, hand]` (startBeat는 0부터, 4박 = 1마디)

```js
const ODE_TO_JOY = {
  title: 'Ode to Joy', composer: 'L. v. Beethoven', bpm: 100, beatsPerBar: 4, leadInBeats: 4,
  notes: [
    // 오른손 (R)
    [64,0,1,'R'],[64,1,1,'R'],[65,2,1,'R'],[67,3,1,'R'],
    [67,4,1,'R'],[65,5,1,'R'],[64,6,1,'R'],[62,7,1,'R'],
    [60,8,1,'R'],[60,9,1,'R'],[62,10,1,'R'],[64,11,1,'R'],
    [64,12,1.5,'R'],[62,13.5,0.5,'R'],[62,14,2,'R'],
    [64,16,1,'R'],[64,17,1,'R'],[65,18,1,'R'],[67,19,1,'R'],
    [67,20,1,'R'],[65,21,1,'R'],[64,22,1,'R'],[62,23,1,'R'],
    [60,24,1,'R'],[60,25,1,'R'],[62,26,1,'R'],[64,27,1,'R'],
    [62,28,1.5,'R'],[60,29.5,0.5,'R'],[60,30,2,'R'],
    // 왼손 (L) — 마디당 온음표, 마지막 마디는 2분음표 2개
    [48,0,4,'L'],[55,4,4,'L'],[48,8,4,'L'],[55,12,4,'L'],
    [48,16,4,'L'],[55,20,4,'L'],[48,24,4,'L'],[55,28,2,'L'],[48,30,2,'L'],
  ],
};
```
- ms 변환: `startMs = startBeat * 60000 / bpm` (템포 배율 적용 시 bpm × rate).
- 기본 모드는 **오른손만**. "양손" 토글 시 왼손 포함. 건반 범위: 오른손만 = C4(60)–E5(76), 양손 = C3(48)–E5(76).
- 곡 카드에는 다른 곡(예: Twinkle Twinkle, Für Elise, River Flows in You, 아리랑 등)도 보여주되
  실제 플레이 가능한 곡은 Ode to Joy 하나여도 된다(나머지는 "데모 곡만 플레이 가능" 표시 또는 같은 데이터 재사용).

### 판정
| 판정 | 허용 오차(절댓값) | 가중치 |
|---|---|---|
| Perfect | ≤ 45 ms | 1.0 |
| Great | ≤ 90 ms | 0.7 |
| Good | ≤ 140 ms | 0.4 |
| Miss | 노트 시각 + 140 ms 지나도록 안 침 | 0 |

- 키 입력 시: 같은 음높이(midi)의 아직 판정 안 된 노트 중 시간상 가장 가까운 것을 ±140ms 안에서 찾아 판정.
- 맞는 노트가 없는 키 입력 = **Wrong** (점수 없음, 콤보 리셋, 해당 건반 빨간 플래시). Miss도 콤보 리셋.
- 판정 시 오차 부호를 기록(음수 = 빠름 Early, 양수 = 느림 Late) → 결과 화면 히스토그램.
- 점수 = `Σ가중치 / 노트수 × 1,000,000` (정수, 천 단위 콤마). 정확도 % = 같은 비율 × 100.
- 랭크: S ≥ 95%, A ≥ 90%, B ≥ 80%, C ≥ 70%, D 그 외. Miss/Wrong 0 = Full Combo, 전부 Perfect = Perfect Play.
- 지연 보정(오프셋) 슬라이더: −100 ~ +100 ms, 입력 시각에서 빼서 판정.

### 입력 (세 가지 모두 지원)
1. **Web MIDI**: `navigator.requestMIDIAccess?.()` — 실패/미지원이어도 에러 없이 조용히 폴백.
   status `0x90` & velocity > 0 = note on, `0x80` 또는 velocity 0 = note off. 기기 연결/해제(`onstatechange`) 반영.
2. **PC 키보드** (오른손 범위): `A=C4 W=C#4 S=D4 E=D#4 D=E4 F=F4 T=F#4 G=G4 Y=G#4 H=A4 U=A#4 J=B4 K=C5 O=C#5 L=D5 P=D#5 ;=E5`
   왼손(양손 모드): `Z=C3 X=D3 C=E3 V=F3 B=G3 N=A3 M=B3` (샵은 생략 가능). 키 반복(`e.repeat`) 무시.
   건반 위에 해당 PC 키 글자를 작게 표시.
3. **마우스/터치**: 화면 건반을 직접 누름 (pointerdown).
- 입력 시각은 `performance.now()` 기준(이벤트의 `timeStamp`도 같은 기준이므로 사용 가능).
- 누른 건반은 하이라이트되고 WebAudio로 간단한 피아노풍 소리(삼각파+빠른 감쇠 엔벨로프)를 낸다.
  오디오는 사용자의 첫 클릭 이후에만 시작(AudioContext resume).

### 진행
- **처음 열면 "데모(자동 연주) 모드"가 무음으로 돌아가고 있어야 한다** — 노트가 떨어지고 자동으로 판정(대부분
  Perfect, 가끔 Great/Good, 아주 가끔 Miss)되어 콤보·점수 애니메이션이 보이는 상태. 썸네일/첫 화면이 살아 있게.
- "▶ 직접 플레이" 버튼 → 4박 카운트인(3·2·1 표시 + 메트로놈 틱) 후 시작. 곡이 끝나면 결과 화면으로.
- 일시정지/재시작, 템포 배율(50% / 75% / 100%), 오른손/양손 토글, 오프셋 슬라이더, 자동 연주 토글.
- 애니메이션 루프는 `requestAnimationFrame`, 화면 그리기는 Canvas 2D 권장(노트 수십 개라 DOM도 무방).
- 노트 길이(지속시간)는 노트 바의 길이로 표현. 판정선(히트 라인)에 노트가 닿는 순간 = 노트 시각.
- 판정 텍스트 팝 애니메이션, 콤보 숫자 범프, 히트 이펙트(파티클/링/글로우), 건반 눌림 이펙트 필수.
- `prefers-reduced-motion`이면 파티클·흔들림을 줄인다.

## 기술 제약 (아티팩트로 게시됨)

- 파일에 `<!doctype>`, `<html>`, `<head>`, `<body>` 태그를 쓰지 않는다(게시 시 자동으로 감싸짐).
  맨 위에 `<title>`과 `<style>`을 두고, 그 다음 마크업, 마지막에 `<script>`.
- 외부 스크립트는 cdnjs.cloudflare.com / cdn.jsdelivr.net/npm / unpkg.com 만, 스타일시트는 Google Fonts만.
  가능하면 라이브러리 없이 바닐라 JS + Canvas. 이미지·아이콘은 인라인 SVG 또는 CSS.
- `alert/confirm/prompt` 금지, iframe(YouTube 임베드) 금지 — YouTube는 링크 텍스트/썸네일 모양만 흉내.
- 폰 폭(약 400px)에서도 동작: 가로 스크롤 금지, 좌우 여백 16px 이상, 플레이 화면은 세로 폰에서도 건반이 보이게.
  `html, body { height:100% }` 기반, `100vh` 대신 `100%`/`dvh`.
- 색은 `:root` 토큰으로 정의. 라이트/다크 둘 다 지원하거나, 의도적으로 한 테마만 쓸 경우 body 배경·모든 색을 명시하고
  다크 단일이면 `:root { color-scheme: dark }`.
- 키보드 포커스 표시, `prefers-reduced-motion` 존중, 모든 폼 컨트롤에 고정 `id`.
- 흔한 AI 디자인 클리셰 금지: 크림색+세리프+테라코타, 보라→파랑 그라데이션 히어로, Inter/Space Grotesk, 이모지 섹션 마커,
  모든 카드에 같은 rounded+shadow, 01/02/03 장식 번호.
- 카피는 한국어(곡명·고유명사는 원어). 사용자 입장의 쉬운 말로.
